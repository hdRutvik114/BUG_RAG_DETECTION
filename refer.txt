# SYSTEM SPECIFICATION PROMPT: CODE-RAG BUG TRACKER & REPAIR APP (MERN-FASTAPI HYBRID)

## 1. PROJECT OVERVIEW & ARCHITECTURE
You are building an industrial-grade, AI-driven Bug Detection and Automated Program Repair web application named "BugIdentifier". 
The core engine shifts the bug detection paradigm from a blind textual machine learning classifier (which suffers from semantic signal starvation and vector overlapping) to a structural, Comparison-Based "Error Mining" / Retrieval-Augmented Generation (RAG) system.

### Core Stack Requirements:
- **Frontend UI**: React.js (Vite, TailwindCSS, Lucide Icons, and Monaco Editor for code views).
- **Backend API Gateway & Agent Core**: FastAPI (Python 3.12) & LangChain (v0.2+).
- **Database & Vector Store**: MongoDB Atlas (acting as both the metadata database and the Vector Store via Atlas Vector Search).
- **Code Parsing Engine**: Babel Parser / Esprima (via a fast Node.js script spawned by FastAPI, or integrated python-babel-parser) to slice JS/TS code into AST-parsed methods.

## 2. THE PIPELINE ENGINE (ARCHITECTURAL BLUEPRINT)
Build the codebase according to the following 11-step architectural flow (modeled on the system blueprint):

1. **INPUT PORTAL**: 
   - Accept either a GitHub Repository URL or an uploaded ZIP file containing a JS/TS project.
2. **PROJECT ANALYSIS**: 
   - Clone/extract the project into an ephemeral directory, analyze project structure, and map local folder/dependency hierarchies.
3. **FILE SELECTION**: 
   - Walk the directory and filter out only relevant source files (`.js`, `.jsx`, `.ts`, `.tsx`). Exclude `node_modules`, build targets, and configuration files.
4. **CODE PARSING (AST)**: 
   - Parse each selected file into an Abstract Syntax Tree (AST) using a Babel parser to locate clean, syntactic method boundaries.
5. **CODE SLICING**: 
   - Slice files into standalone, independent method/function-level code chunks.
6. **FEATURE LAYER (HYBRID COGNITION)**:
   - For each sliced code chunk, generate:
     - **AST Vectors (120-D)**: A structural representation capturing local tree geometry.
     - **Pretrained Embeddings**: Dense vector representations of the code sequence (using `text-embedding-3-small` or `codebert-base` embeddings).
     - **Static Analysis Features**: Compute static metrics (Cyclomatic Complexity, line counts, dependency lists).
7. **ML BUG DETECTOR (RETRIEVAL GATEKEEPER)**:
   - Instead of a traditional binary classifier (which has an unreliable AUC of ~0.52 in isolation), use the vector representation to perform a similarity lookup against the database of historical bug-fix commits (your "Delta Dataset").
   - **Learned Confidence Filter**:
     - `Similarity Score < 0.80`: Classify as Clean (Cost: \$0.00, do not send to LLM).
     - `Similarity Score >= 0.80`: Flag as Suspicious, extract metadata, and pass to the LLM verification gate.
8. **EVIDENCE EXTRACTION (HISTORICAL DATASET)**:
   - When similarity hits the threshold, retrieve the following linked records from MongoDB:
     - The matching historical **Buggy Code ("Before" Commit)**.
     - The matching historical **Fixed Code ("After" Commit)**.
     - **The pre-computed Delta Signature** (e.g., `added_boundary_check = 1`, `added_await = 0`, `delta_op_gt = -1`) representing the transformation DNA of the original repair.
9. **LANGCHAIN AGENT VERIFICATION & REPAIR**:
   - Construct a Few-Shot In-Context Learning prompt inside LangChain:
     - Feed the LLM (GPT-4o) the retrieved Buggy Code, Fixed Code, and the Delta Signature as an explicit transformation blueprint.
     - Ask the LLM to verify if the user's Suspicious Code contains the same underlying bug. If yes, generate the specific structural patch.
10. **JSON OUTBOX ENCAPSULATION**:
    - Return a clean, verified JSON schema detailing: file path, start/end lines, bug category, severity level, technical explanation, and the side-by-side patch code.
11. **RESULTS WEB APP DISPLAY**:
    - Present the findings to the developer in an interactive dashboard.

***

### Why this is a superior design for your project:
1. **Explainable AI**: Your UI displays the actual historical commit message that matched the bug [5/175, 9/323]. This builds immediate trust with developers because they can see *why* the code was flagged.
2. **Mitigates Hallucinations**: Standard LLMs often fail to fix bugs when analyzing standalone methods [4/153]. Feeding the pre-calculated structural **Delta Signatures** directly instructs the model on the exact transformation pattern it needs to execute [4/150, 7/253].
3. **Optimized API Billing**: By filtering out healthy code blocks locally using vector retrieval and learned confidence thresholds before sending them to LangChain, your API consumption costs drop significantly [2/36, 9/336].
